# Spec: 后台系统用户

**定稿日期**：2026-10-22
**对应迁移**：`db/schema/004_app_users.sql`
**架构决策**：`docs/decisions/0004-app-users.md`

## 背景

本地 Web 后台需要可登录的操作账号，以及用户管理板块。与买米客户 `customers` 分开。

## 表设计

### app_users

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| username | VARCHAR(64) | UNIQUE, NOT NULL | 登录名 |
| password_hash | TEXT | NOT NULL | 密码哈希，禁止明文 |
| display_name | VARCHAR(64) | NOT NULL | 界面显示名 |
| role | VARCHAR(16) | NOT NULL, CHECK | `admin` / `operator` |
| status | VARCHAR(16) | NOT NULL, DEFAULT 'active', CHECK | `active` / `disabled` |
| last_login_at | TIMESTAMPTZ | NULL | 最近登录 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | |
| updated_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | |

索引：

- `username` 唯一索引（自动）
- `idx_app_users_status`：`(status)`

## 应用层约定

1. 写入前用 bcrypt（或同等）生成 `password_hash`。
2. 登录成功时更新 `last_login_at`。
3. `status = disabled` 的账号拒绝登录。
4. 角色权限细节（哪些菜单可见）在 Web 层实现，本表只存角色标签。

## 关键决策

1. 与 `customers` 分离。
2. 暂不软删除；停用用 `disabled`。
3. 暂不建「角色权限」多对多表；两档角色够用。
