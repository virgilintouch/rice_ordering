# Spec: 订单

**定稿日期**：2026-10-22
**对应迁移**：`db/schema/003_orders.sql`
**架构决策**：`docs/decisions/0003-orders-model.md`

## 背景

用户需要记录每笔大米订单：客户、收货信息、选用价档、包数，以及下单当时的价格。历史订单不随后续改价、改地址而变化。

## 业务上下文

- 按包销售。金额 = `unit_price_per_jin × jin_per_pack × pack_count`。
- 四档价：普通零售 / 真空零售 / 普通 VIP / 真空 VIP，对应 `price_tier`。
- 售价已含运费；真空售价另含真空费。订单金额不再另加运费或真空费。
- 普通包装订单的 `vacuum_fee_per_jin` 记 `0`。
- 状态：`ordered` → `paid` → `shipped` → `delivered`。暂无取消。

## 计算

毛利不建列。每斤毛利：

```text
unit_price_per_jin - rice_cost_per_jin - shipping_fee_per_jin - vacuum_fee_per_jin
```

整单毛利 = 每斤毛利 × `jin_per_pack` × `pack_count`。

```sql
SELECT
  order_no,
  amount,
  (unit_price_per_jin - rice_cost_per_jin - shipping_fee_per_jin - vacuum_fee_per_jin)
    * jin_per_pack * pack_count AS gross_margin
FROM orders
WHERE status <> 'ordered';  -- 示例：可按业务改过滤
```

## 下单写入口径（应用层）

1. 选定客户、地址、价目年、价档、包数。
2. 从 `customer_addresses` 抄收件人、电话、地址。
3. 从 `rice_year_prices` 抄 `jin_per_pack`、成本、运费、真空费，以及对应价档售价到 `unit_price_per_jin`。
4. 普通包装：`vacuum_fee_per_jin = 0`。
5. 计算并写入 `amount`。
6. `status = 'ordered'`，填 `ordered_at`。

## 关键决策

1. 关联 + 收货快照 + 价格快照并存。
2. 暂无 `cancelled`。
3. 毛利只在查询时用快照计算。

## 拒绝的替代方案

| 方案 | 拒绝理由 |
|---|---|
| 只存外键不存快照 | 改地址、改价后历史失真 |
| 状态含 cancelled | 当前不需要 |
